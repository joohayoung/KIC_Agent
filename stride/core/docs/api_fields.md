### 1.1 접수번호(rcept_no)와 접수일(rcept_dt) ⚠️

- `rcept_no` = 14자리. 앞 8자리는 날짜. 9번째 자리 `8`은 거래소 공시(I)로 보임 (예: `2026110380xxxx`).
- **앞 8자리 ≠ `rcept_dt`인 경우가 있다.** list.json 실제 행: `rcept_no=20260617000513`, `rcept_dt=20260618`. 확인한 경우는 모두 앞 8자리가 접수일보다 하루 빨랐다.
- **결정(2026-11-04): 시점 판정은 list.json `rcept_dt`만 쓴다.** `rcept_no` 날짜 해석 코드는 삭제했다 (`core.asof`).

### 1.2 정정공시 반영 방식 ⚠️ (시점 통제에 영향)

DS005, fnlttSinglAcntAll, accnutAdtorNmNdAdtOpinion은 **정정 후 최신본 1건만** 돌려준다. 원공시 값은 받을 수 없다.

| API | 실제 동작 |
|---|---|
| DS005 (piicDecsn) | 표본 B: 원공시 `20260910…` → 정정 `20260922…`. `bgn_de=end_de=20260910` 조회 시 **정정본 rcept_no `20260922…`** 1행 반환. `bgn_de=end_de=20260922` 조회 시 0행. → 기간 필터는 **원공시 접수일**, 반환 값·rcept_no는 **최신 정정본** |
| DS005 (bdwtIsDecsn) | 원공시 `20251224…` 표본을 조회하면 정정본 `20260123…` 반환 (같은 동작) |
| fnlttSinglAcntAll | 표본 A 2025 사업보고서: 원본 `20260312…`(2026-03-12) 대신 정정본 `20260515…`(2026-05-15) rcept_no로 반환. 2024 사업보고서도 정정본(`20250814…`) |
| 감사의견 | 표본 A 2025 FY: 정정본 rcept_no `20260515…` |
